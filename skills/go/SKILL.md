# Go API quality

## Layout

- `cmd/api` wires dependencies; `internal/httpapi` is transport; business logic lives in `internal/<domain>` packages with interfaces at the consumer side.
- `internal/db` is generated by sqlc (or holds the one data layer per the ADR). Handlers never import `database/sql` directly (ADR rule).

## Errors

- Wrap with context: `fmt.Errorf("load invoice %s: %w", id, err)`; compare with `errors.Is/As`.
- Handlers map domain errors to HTTP status in one place; never return raw error strings to clients.

## Context and concurrency

- Every function that does I/O takes `ctx context.Context` first and respects cancellation.
- Outbound HTTP uses a client with timeouts; servers set `ReadHeaderTimeout`.
- Goroutines have an owner and an exit path (errgroup); no fire-and-forget.

## Data

- pgx pool (`pgxpool`) shared via dependency injection; transactions with `pgx.BeginFunc`.
- Money is integer cents; time is UTC `time.Time`.

## Observability

- `log/slog` only (JSON handler), with request id and trace id attributes; never log secrets or tokens (ADR rule bans `log.Print`/`fmt.Print`).
- `otelhttp` middleware for traces when telemetry is on.

## Gates

- `go build ./... && go vet ./...`, `golangci-lint run` (config in `.golangci.yml`), `go test -race ./...`.
- Table-driven tests; `httptest` for handlers.
